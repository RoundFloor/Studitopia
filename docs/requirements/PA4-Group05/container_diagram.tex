\hypertarget{sec:2-purpose-and-scope}{}
\addcontentsline{toc}{subsection}{2. Purpose and Scope}
\subsection*{2. Purpose and Scope}
\par\medskip

This document zooms into the \texttt{Studitopia} system box from the Level 1 System Context diagram. It shows the major runnable containers, the technologies used by each, and how they communicate.
\par\medskip

Backend, database, and local file storage are drawn inside one server boundary because they are hosted together. The compiled React frontend is returned by the backend NestJS Web package rather than served by a separate production frontend server. Vite hosts the SPA on port \texttt{8999} only during development.
\par\medskip

\hypertarget{sec:3-architecture-constraints-and-hosting-model}{}
\addcontentsline{toc}{subsection}{3. Architecture Constraints and Hosting Model}
\subsection*{3. Architecture Constraints and Hosting Model}
\par\medskip

\begin{itemize}
\item Studitopia is delivered as a browser-based web application. Users do not install a native client.
\item The backend and PostgreSQL database are hosted on the same server.
\item Vite hosts the frontend on port \texttt{8999} only during development; deployed frontend assets are served by the NestJS Web package from the backend server.
\item The backend responds to frontend requests and returns compiled HTML, JavaScript, and CSS assets that the browser renders.
\item The browser never connects directly to PostgreSQL. All application data passes through the NestJS backend API.
\item Local filesystem storage is used for uploaded assets such as avatars; no cloud object-storage provider is currently configured.
\item Email delivery uses an external Resend API, with a Discord webhook fallback for OTP delivery.
\item Planned capabilities such as full AI matching, cloud file scanning, OAuth sign-in, voice/livestream collaboration, and push notifications are not current runtime dependencies.
\end{itemize}

\hypertarget{sec:5-2-container-communication-notes}{}
\addcontentsline{toc}{subsubsection}{5.2 Container Communication Notes}
\subsubsection*{5.2 Container Communication Notes}
\par\medskip

\begin{itemize}
\item The browser never connects directly to PostgreSQL or the filesystem. All application data and file access pass through the backend API.
\item There is no separate production frontend server. In deployment, the NestJS Web package's \texttt{WebController} reads the compiled frontend bundle and returns \texttt{index.html} for SPA fallback.
\item Vite on port \texttt{8999} is used only for local development; it is not a deployment target and does not replace the backend Web package.
\item Backend, database, and local file storage share one server; this is why they are drawn inside the same server boundary.
\item Communication is synchronous HTTP/HTTPS for browser-to-backend and backend-to-external-service calls, the PostgreSQL wire protocol for backend-to-database calls, and local filesystem I/O for backend-to-storage calls.
\item No WebSocket container or external real-time service is currently wired in the source, even though earlier phases discuss live collaboration.
\end{itemize}

\hypertarget{sec:9-assumptions-and-deferred-capabilities}{}
\addcontentsline{toc}{subsection}{9. Assumptions and Deferred Capabilities}
\subsection*{9. Assumptions and Deferred Capabilities}
\par\medskip

\begin{itemize}
\item The architecture documents describe the current implementation plus the documented PA1-PA4 product direction.
\item Backend and database sharing one server is a deliberate deployment constraint; this is shown in the Level 2 diagram. Scaling would require a revised container design.
\item Because the backend Web package serves the compiled React application in deployment, frontend and backend releases must be deployed together on the same server.
\item Vite on port \texttt{8999} is a development-only host and is not part of the deployed system.
\item External service credentials and webhook URLs are intentionally omitted.
\item All four architecture documents must be updated whenever source code changes container boundaries, component responsibilities, endpoints, or external dependencies.
\end{itemize}
