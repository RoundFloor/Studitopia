\hypertarget{sec:2-purpose-and-scope}{}
\addcontentsline{toc}{subsection}{2. Purpose and Scope}
\subsection*{2. Purpose and Scope}
\par\medskip

This document shows Studitopia as a whole, the human actors who interact with it, and the external systems it depends on. It describes the accumulated product direction from PA1 through PA4 while distinguishing documented requirements from the runtime behavior currently present in the source code.
\par\medskip

\hypertarget{sec:2-1-source-accurate-implementation-status}{}
\addcontentsline{toc}{subsubsection}{2.1 Source-Accurate Implementation Status}
\subsubsection*{2.1 Source-Accurate Implementation Status}
\par\medskip

\begin{itemize}
\item Implemented frontend routes are \texttt{/auth/login}, \texttt{/auth/register}, \texttt{/auth/recover\_password}, \texttt{/auth/recover\_otp}, \texttt{/auth/set\_password}, \texttt{/auth/verify\_otp}, and \texttt{/forum}.
\item Implemented backend endpoints cover authentication/OTP, account read and avatar upload, forum browse, post/tag read, file read, and SPA asset delivery.
\item Vite hosts the frontend on port \texttt{8999} only during development. In deployment, the NestJS Web package serves the compiled frontend, so there is no separate production frontend server.
\item There are no implemented frontend or backend routes for friends, meeting rooms, notifications, profile editing beyond avatar upload, or full resource-library management; these remain documented product requirements and future work.
\item \texttt{ReCaptchaService} is a stub and is not imported by \texttt{AppModule}; \texttt{WebService}/\texttt{WebBased()} are defined but not applied to routes.
\end{itemize}
\par\medskip

\hypertarget{sec:3-1-explanation-of-the-diagram}{}
\addcontentsline{toc}{subsubsection}{3.1 Explanation of the Diagram}
\subsubsection*{3.1 Explanation of the Diagram}
\par\medskip

\textbf{Studitopia} is the system at the center. At Level 1 it is intentionally shown as a single box, even though internally it contains a NestJS/Express backend, a compiled React+TypeScript frontend, PostgreSQL, and local file storage. The backend, database, and file storage are hosted on the same server. During development, Vite hosts the SPA on port \texttt{8999}; in deployment, the NestJS Web package serves the compiled frontend assets to the browser, so no separate production frontend host exists.
\par\medskip

\textbf{University Student} is the primary actor. At the requirements level, students register and verify university email, log in, manage profiles and preferences, browse and search the university forum, create posts, comment and answer, vote, save posts, share resources, manage friends and groups, join or create meeting rooms, and receive notifications. The current source implements authentication/OTP, account display and avatar upload, forum browse, and partially static feed/library views.
\par\medskip

\textbf{Moderator / Administrator} is the secondary requirements-level actor responsible for trust and safety. No moderator-specific routes or components are implemented in the current source.
\par\medskip

\textbf{Web Browser} is the client software used by both human actors. It requests pages and API data from Studitopia. The backend returns the compiled React HTML, JavaScript, CSS, and JSON responses; the browser executes the frontend code and renders the UI. In development those assets come from Vite on port \texttt{8999}; in deployment they come from the backend Web package.
\par\medskip

\textbf{Resend Email API} delivers OTP and recovery emails. \textbf{Discord Webhook} is the fallback OTP path. \textbf{Google Fonts} is a presentational external dependency loaded by the browser.
\par\medskip

The browser does not access the database directly. The backend is the only runtime client of PostgreSQL and exposes the \texttt{api/v1} surface consumed by the React frontend.
\par\medskip
