\subsubsection*{A4. Model Notes}
\par\medskip

\begin{enumerate}
\item UC-09 covers automatic termination after inactivity; manual logout is outside its scope and belongs to UC-08.
\item The 15-minute value comes from FR-04.1 and AC-04.1; NFR-SEC-7 states 30 minutes, so the conflict is recorded rather than silently resolved in the model.
\item Activity reset, protected-access denial, and expiration messaging are internal behavior because no separate include or extend use case is named.
\item No new I-xx, E-xx, or G-xx identifiers are introduced; the model contains only the primary actor and the selected base use case.
\end{enumerate}
\par\medskip

\hypertarget{sec:part-b-use-case-specification}{}
\addcontentsline{toc}{subsection}{Part B --- Use Case Specification}
\subsection*{Part B --- Use Case Specification}
\par\medskip

\hypertarget{sec:b1-brief-description}{}
\addcontentsline{toc}{subsubsection}{B1. Brief Description}
\subsubsection*{B1. Brief Description}
\par\medskip

The system automatically logs out an inactive user so an unattended account remains secure. After a successful login, no requests from the user for 15 consecutive minutes cause the session to terminate and the user to be logged out, as stated by FR-04.1 and AC-04.1.
\par\medskip

When the session has expired, protected pages and APIs deny access and require login again. The login redirect includes a message informing the user that the session expired; no exact message wording is provided in the proposals.
\par\medskip

\hypertarget{sec:b2-preconditions}{}
\addcontentsline{toc}{subsubsection}{B2. Preconditions}
\subsubsection*{B2. Preconditions}
\par\medskip

\begin{enumerate}
\item The user has successfully logged in and has an active session.
\item The inactivity timer is maintained by the frontend and backend as specified by FR-04.1 and FR-04.3.
\item The user does not send a qualifying request before the applicable timeout.
\end{enumerate}
\par\medskip

\hypertarget{sec:b3-postconditions}{}
\addcontentsline{toc}{subsubsection}{B3. Postconditions}
\subsubsection*{B3. Postconditions}
\par\medskip

\begin{enumerate}
\item \textbf{Success:} The inactive session is terminated and the user is logged out.
\item \textbf{Success:} The user is redirected to Login and informed that the session expired.
\item \textbf{Success:} Protected pages and APIs deny access using the expired session.
\item \textbf{Failure:} If a qualifying request is received before the timeout, the inactivity timer is reset and the session remains active.
\end{enumerate}
\par\medskip

\hypertarget{sec:b4-main-success-scenario-basic-flow}{}
\addcontentsline{toc}{subsubsection}{B4. Main Success Scenario (Basic Flow)}
\subsubsection*{B4. Main Success Scenario (Basic Flow)}
\par\medskip

\begin{enumerate}
\item The user completes login and receives an active session.
\item The system starts or maintains the inactivity timer for that session.
\item The system receives no requests from the user for 15 consecutive minutes, according to FR-04.1 and AC-04.1.
\item The system automatically terminates the session and logs the user out.
\item The user attempts to continue using the application or is redirected to Login.
\item The system displays a message informing the user that the session expired and requires login again.
\end{enumerate}
\par\medskip

\hypertarget{sec:b5-alternative-flows}{}
\addcontentsline{toc}{subsubsection}{B5. Alternative Flows}
\subsubsection*{B5. Alternative Flows}
\par\medskip

The story specifies no distinct alternative flow; the source-backed variant is activity before the timeout.
\par\medskip

\hypertarget{sec:a1-session-reset-on-activity}{}
\paragraph*{A1. Session reset on activity}
\par\medskip

At basic flow step 3, a new qualifying request is received before the timeout. The system resets the inactivity timer, keeps the session active, and resumes normal use of the protected page or API (FR-04.3, AC-04.3).
\par\medskip

\hypertarget{sec:b6-exception-flows}{}
\addcontentsline{toc}{subsubsection}{B6. Exception Flows}
\subsubsection*{B6. Exception Flows}
\par\medskip

\hypertarget{sec:e1-protected-page-access-after-session-expiration}{}
\paragraph*{E1. Protected page access after session expiration}
\par\medskip

The user attempts to open a protected page after expiry. The system denies access, redirects to Login, displays the session-expiration message, and requires the user to log in again (FR-04.2, FR-04.4, AC-04.2, AC-04.4).
\par\medskip

\hypertarget{sec:e2-protected-api-access-after-session-expiration}{}
\paragraph*{E2. Protected API access after session expiration}
\par\medskip

The user or frontend sends a protected API request after expiry. The system denies access and requires a new login; no automatic-renewal behavior is specified in the proposals (FR-04.2, AC-04.2).
\par\medskip

\hypertarget{sec:b7-business-rules}{}
\addcontentsline{toc}{subsubsection}{B7. Business Rules}
\subsubsection*{B7. Business Rules}
\par\medskip

\begin{enumerate}
\item After 15 consecutive minutes with no requests, the system automatically terminates the session and logs the user out (FR-04.1, AC-04.1).
\item NFR-SEC-7 states 30 minutes for inactive authentication sessions; this conflicts with FR-04.1 and AC-04.1 and is not silently overridden.
\item A protected page or API must deny access after session expiration and require login again (FR-04.2, AC-04.2).
\item A qualifying request received before the timeout resets the inactivity timer (FR-04.3, AC-04.3).
\item The login redirect after expiration must inform the user that the session expired (FR-04.4, AC-04.4).
\item Protected resources require authentication, and authorization checks must remain server-side (NFR-SEC-1, NFR-SEC-6).
\end{enumerate}
\par\medskip

\hypertarget{sec:b10-interface-and-data-notes}{}
\addcontentsline{toc}{subsubsection}{B10. Interface and Data Notes}
\subsubsection*{B10. Interface and Data Notes}
\par\medskip

\begin{itemize}
\item \textbf{Confirmed requirement --- screen/flow path:} Automatic logout returns the user to Login; \texttt{screen\_flow.md} shows \texttt{Home → Logout} and the Authentication area with \texttt{Login}.
\item \textbf{Confirmed requirement --- UI behavior:} The system informs the user that the session expired and requires login again; no exact quoted message text is specified.
\item \textbf{Confirmed requirement --- session data:} \texttt{settings.md} names \texttt{sessionId}, \texttt{startedAt}, \texttt{lastActivityAt}, and \texttt{expiresAt} for session summary and inactivity feedback.
\item \textbf{Confirmed requirement --- policy conflict handling:} \texttt{settings.md} recommends the stricter 15-minute value unless the product explicitly decides otherwise.
\item \textbf{API endpoint:} Not specified in proposals; \texttt{API.md} has no dedicated automatic-logout endpoint.
\item \textbf{Statuses and error codes:} Not specified in proposals for automatic logout itself; \texttt{API.md} generally defines \texttt{UNAUTHORIZED} 401, and no inactivity-specific error code appears in \texttt{response\_code.md}.
\item \textbf{Notification/privacy rules:} The only specified feedback is the session-expiration notice on redirect to Login; no email or notification-center message is specified.
\item \textbf{Recommendation only:} \texttt{/settings} and the Account Settings session summary are recommended UI groupings in \texttt{settings.md}, not proposal-defined routes.
\end{itemize}
\par\medskip

\hypertarget{sec:b11-source-alignment-notes}{}
\addcontentsline{toc}{subsubsection}{B11. Source Alignment Notes}
\subsubsection*{B11. Source Alignment Notes}
\par\medskip

\begin{itemize}
\item FR-04.1 and AC-04.1 require logout after 15 minutes of inactivity, while NFR-SEC-7 states 30 minutes; \texttt{settings.md} recommends the stricter 15-minute value unless the product explicitly decides otherwise.
\item UC-02 Log In already treats session expiry as a protected-access exception and lists NFR-SEC-7; UC-09 details the inactivity trigger, timer reset, denial, and notice without duplicating login credential behavior.
\item \texttt{API.md} has no dedicated automatic-logout endpoint; expired access is enforced through denial of protected pages and APIs rather than a documented route.
\item UC-01 Register Account can create an initial session, but it does not define inactivity policy; whether that session follows the same timeout is not specified in the proposals.
\item No new I-xx, E-xx, or G-xx identifiers were created; the focused model uses only UC-09 and its primary actor.
\end{itemize}
