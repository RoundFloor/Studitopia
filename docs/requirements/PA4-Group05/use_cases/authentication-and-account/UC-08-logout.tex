\hypertarget{sec:a4-model-notes}{}
\addcontentsline{toc}{subsubsection}{A4. Model Notes}
\subsubsection*{A4. Model Notes}
\par\medskip

\begin{enumerate}
\item UC-08 is limited to ending the current authenticated session; it does not model login, registration, password recovery, or account deletion.
\item Client cleanup and backend invalidation are internal behavior of UC-08 because the proposals do not name a separate included use case.
\item The logout action is available after navigation to Settings or from global navigation, but no distinct UI actor or supporting service is specified.
\item No new I-xx, E-xx, or G-xx identifiers are introduced; the model contains only the primary actor and the selected base use case.
\end{enumerate}
\par\medskip

\par\medskip

\hypertarget{sec:b1-brief-description}{}
\addcontentsline{toc}{subsubsection}{B1. Brief Description}
\subsubsection*{B1. Brief Description}
\par\medskip

A logged-in user ends the current session to protect the account when using a shared device or when finished with the platform. The system clears authentication tokens and temporary user data from local and session storage and invalidates the active backend session.
\par\medskip

The screen flow places logout after Home or Settings and returns the user to Login. Settings groups the control as a global account action labeled \textbf{Log out}.
\par\medskip

\hypertarget{sec:b2-preconditions}{}
\addcontentsline{toc}{subsubsection}{B2. Preconditions}
\subsubsection*{B2. Preconditions}
\par\medskip

\begin{enumerate}
\item The user has an active authenticated session.
\item The user can reach the logout control from Settings or global navigation.
\item The frontend and backend are available to perform cleanup and session invalidation.
\end{enumerate}
\par\medskip

\hypertarget{sec:b3-postconditions}{}
\addcontentsline{toc}{subsubsection}{B3. Postconditions}
\subsubsection*{B3. Postconditions}
\par\medskip

\begin{enumerate}
\item \textbf{Success:} Authentication tokens and temporary user data are cleared from local and session storage.
\item \textbf{Success:} The active backend session is invalidated and the user is returned to Login.
\item \textbf{Failure:} If cleanup or invalidation does not complete, the source documents do not specify a recovery message or retries.
\end{enumerate}
\par\medskip

\hypertarget{sec:b4-main-success-scenario-basic-flow}{}
\addcontentsline{toc}{subsubsection}{B4. Main Success Scenario (Basic Flow)}
\subsubsection*{B4. Main Success Scenario (Basic Flow)}
\par\medskip

\begin{enumerate}
\item The logged-in user opens Settings or uses global navigation.
\item The system displays the \textbf{Log out} control.
\item The user selects \textbf{Log out}.
\item The frontend clears authentication tokens and temporary user data from local and session storage.
\item The backend invalidates the user's active session.
\item The system redirects the user to Login.
\end{enumerate}
\par\medskip

\hypertarget{sec:b7-business-rules}{}
\addcontentsline{toc}{subsubsection}{B7. Business Rules}
\subsubsection*{B7. Business Rules}
\par\medskip

\begin{enumerate}
\item A logged-in user is allowed to log out of the account (FR-03.1).
\item On logout, all authentication tokens and temporary user data stored in local and session storage must be cleared (FR-03.2, AC-03.1).
\item On logout, the user's active session must be invalidated on the backend (FR-03.3, AC-03.2).
\item UI must appear exactly as designed, and navigation buttons must work correctly (AC-03.3, AC-03.4).
\item After logout, protected user resources remain subject to authentication requirements (NFR-SEC-1).
\end{enumerate}

\hypertarget{sec:b10-interface-and-data-notes}{}
\addcontentsline{toc}{subsubsection}{B10. Interface and Data Notes}
\subsubsection*{B10. Interface and Data Notes}
\par\medskip

\begin{itemize}
\item \textbf{Confirmed requirement --- screen/flow path:} \texttt{Home → Settings → Logout → Login}; \texttt{Home → Logout} from the screen flow; feature-flow logout follows the authenticated main pages.
\item \textbf{Confirmed requirement --- UI text:} The control is labeled \textbf{Logout} in \texttt{userstory.md} and \texttt{screen\_flow.md}, and \textbf{Log out} in \texttt{settings.md}.
\item \textbf{Confirmed requirement --- UI actions:} \texttt{LogoutButton} ends the current session and clears local/session authentication data; no confirmation dialog is specified for logout.
\item \textbf{Confirmed requirement --- data cleanup:} Authentication tokens and temporary user data in local and session storage must be cleared; backend session state must be invalidated.
\item \textbf{Data model note:} \texttt{settings.md} names \texttt{sessionId}, \texttt{startedAt}, \texttt{lastActivityAt}, and \texttt{expiresAt} as session fields; this is a settings information-model detail rather than an API field list.
\item \textbf{API endpoint:} Not specified in proposals; \texttt{API.md} has no logout endpoint.
\item \textbf{Statuses and error codes:} Not specified in proposals for logout itself; \texttt{API.md} generally defines \texttt{UNAUTHORIZED} 401 for protected endpoints, and no logout-specific error code appears in \texttt{response\_code.md}.
\item \textbf{Notification/privacy rules:} No logout-specific notification is specified; protected access after logout requires login according to NFR-SEC-1.
\item \textbf{Recommendation only:} \texttt{settings.md} recommends \texttt{/settings} and Account Settings grouping; the route is not defined in the proposal flow documents.
\end{itemize}
\par\medskip

\hypertarget{sec:b11-source-alignment-notes}{}
\addcontentsline{toc}{subsubsection}{B11. Source Alignment Notes}
\subsubsection*{B11. Source Alignment Notes}
\par\medskip

\begin{itemize}
\item \texttt{API.md} defines \texttt{POST /auth/login} but has no logout endpoint, while FR-03.1, FR-03.2, FR-03.3, AC-03.1, and AC-03.2 require logout, cleanup, and invalidation.
\item UC-02 Log In creates the authenticated session handled by UC-08 and already notes the missing logout endpoint; UC-08 does not repeat credential validation, CAPTCHA, or Google login behavior.
\item UC-01 Register Account can establish an initial authenticated session, but it does not define logout behavior; UC-08 applies to that session only after the user is logged in.
\item AC-03.3 and AC-03.4 are UI and navigation validation requirements; no exact screen mockup or logout message text is provided in the proposal sources.
\item No new I-xx, E-xx, or G-xx identifiers were created; the focused model uses only UC-08 and its primary actor.
\end{itemize}
