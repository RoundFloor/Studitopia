\par\medskip

\hypertarget{sec:b1-brief-description}{}
\addcontentsline{toc}{subsubsection}{B1. Brief Description}
\subsubsection*{B1. Brief Description}
\par\medskip

A university student creates and updates a profile so that other users can understand their academic background and interests. The profile includes an avatar, short bio, display name, university, major, and academic year, with university and major selected from the supported catalog.
\par\medskip

The student can preview how the profile appears to other members before saving. Valid changes are persisted and reflected across active sessions, while invalid avatar files, moderated text, or unsupported catalog values block the save.
\par\medskip

\hypertarget{sec:b2-preconditions}{}
\addcontentsline{toc}{subsubsection}{B2. Preconditions}
\subsubsection*{B2. Preconditions}
\par\medskip

\begin{enumerate}
\item The student is authenticated before accessing protected profile settings (NFR-SEC-1).
\item A profile record exists or can be created for the student (FR-08.1).
\item Supported university and major catalog data are available (FR-08.3, AC-08.2).
\item The student has opened \textbf{Settings} and selected \textbf{Profile} from the main navigation.
\end{enumerate}
\par\medskip

\hypertarget{sec:b3-postconditions}{}
\addcontentsline{toc}{subsubsection}{B3. Postconditions}
\subsubsection*{B3. Postconditions}
\par\medskip

\begin{enumerate}
\item \textbf{Success:} Valid profile changes are persisted and reflected across the user's active sessions (FR-08.5, AC-08.4).
\item \textbf{Success:} The saved profile shows university, major, and academic year on the public forum profile as permitted by privacy settings (FR-08.6).
\item \textbf{Failure:} Invalid avatar, text, or catalog input blocks the save and the previously saved profile remains in effect.
\end{enumerate}
\par\medskip

\hypertarget{sec:b4-main-success-scenario-basic-flow}{}
\addcontentsline{toc}{subsubsection}{B4. Main Success Scenario (Basic Flow)}
\subsubsection*{B4. Main Success Scenario (Basic Flow)}
\par\medskip

\begin{enumerate}
\item The student selects \textbf{Settings} and then \textbf{Profile} from the main navigation (\texttt{Home → Settings → Profile}).
\item The system displays \texttt{ProfileSettingsForm} with \textbf{Edit Display Name}, \textbf{Edit Avatar}, \textbf{Edit Description}, \textbf{Edit University / Major}, \textbf{Edit Hobbies}, \textbf{Edit Often Free Time}, and \textbf{Submit} controls from the profile settings flow.
\item The student edits the display name, short bio, university, major, academic year, hobbies, or free time, and optionally uploads and crops a new avatar.
\item Where supported, the student chooses \textbf{Hidden / Visible} for the description or hobbies field.
\item \texttt{ProfilePreviewPane} updates to show the profile as other members see it.
\item The student selects \textbf{Update Profile} or \textbf{Save Changes}.
\item The system validates image type and size, display name and bio content, and catalog selections.
\item The system persists valid changes, reflects them across active sessions, and displays \textbf{Profile updated}.
\end{enumerate}
\par\medskip

\hypertarget{sec:b5-alternative-flows}{}
\addcontentsline{toc}{subsubsection}{B5. Alternative Flows}
\subsubsection*{B5. Alternative Flows}
\par\medskip

No distinct alternative flow is stated in US-08; the following source-backed variants are recorded.
\par\medskip

\hypertarget{sec:a1-profile-update-without-an-avatar-change}{}
\paragraph*{A1. Profile update without an avatar change}
\par\medskip

At basic flow step 3, the student changes only text or academic fields. No avatar validation or cropping is performed.
\par\medskip

\hypertarget{sec:a2-field-visibility-selected-during-profile-editing}{}
\paragraph*{A2. Field visibility selected during profile editing}
\par\medskip

At basic flow step 4, the student follows \texttt{Edit Description → Privacy (Hidden | Visible)} or \texttt{Edit Hobbies → Privacy}, then \texttt{Privacy → Submit}; the saved visibility is enforced with UC-14.
\par\medskip

\hypertarget{sec:a3-discard-before-saving}{}
\paragraph*{A3. Discard before saving}
\par\medskip

Before basic flow step 6, the student selects \textbf{Discard} in the recommended \texttt{SettingsActionBar}; unsaved edits are reverted and no persistence occurs.
\par\medskip

\hypertarget{sec:b6-exception-flows}{}
\addcontentsline{toc}{subsubsection}{B6. Exception Flows}
\subsubsection*{B6. Exception Flows}
\par\medskip

\hypertarget{sec:e1-invalid-avatar-file}{}
\paragraph*{E1. Invalid avatar file}
\par\medskip

If the uploaded file is not PNG, JPG, or WEBP, exceeds 5MB, or cannot be cropped to 1:1, the system blocks the save and reports the validation error (AC-08.5).
\par\medskip

\hypertarget{sec:e2-profanity-filter-rejection}{}
\paragraph*{E2. Profanity filter rejection}
\par\medskip

If the display name or bio text fails the automated profanity filter, the system blocks the save and shows an inline validation error as recommended in \texttt{settings.md} (AC-08.6).
\par\medskip

\hypertarget{sec:e3-unsupported-catalog-selection}{}
\paragraph*{E3. Unsupported catalog selection}
\par\medskip

If the student's university or major is not present in the supported catalog, the system blocks the save and requires a catalog-backed selection (FR-08.3, AC-08.2).
\par\medskip

\hypertarget{sec:b7-business-rules}{}
\addcontentsline{toc}{subsubsection}{B7. Business Rules}
\subsubsection*{B7. Business Rules}
\par\medskip

\begin{enumerate}
\item A user can create and update their own profile (FR-08.1).
\item The profile includes display name, username, avatar, short bio, university, major, and academic year (FR-08.2, AC-08.1).
\item University and major must be selected from the supported catalog (FR-08.3, AC-08.2).
\item Avatar uploads accept only PNG, JPG, and WEBP, enforce a maximum size of 5MB, and auto-crop to 1:1 (AC-08.5).
\item Display names and bio text must pass automated profanity filters before changes are saved (AC-08.6).
\item Profile changes must be saved immediately and reflected across all active sessions (FR-08.5, AC-08.4).
\end{enumerate}
\par\medskip

\hypertarget{sec:b10-interface-and-data-notes}{}
\addcontentsline{toc}{subsubsection}{B10. Interface and Data Notes}
\subsubsection*{B10. Interface and Data Notes}
\par\medskip

\begin{itemize}
\item Screen/flow path: \texttt{Home → Settings → Profile}; profile settings flow \texttt{Profile → Edit Display Name → Submit}, \texttt{Edit Avatar → Submit}, \texttt{Edit Description → Submit}, \texttt{Edit University / Major → Submit}, \texttt{Edit Hobbies → Submit}, \texttt{Edit Often Free Time}, \texttt{Edit Description → Privacy (Hidden | Visible)}, \texttt{Edit Hobbies → Privacy}, \texttt{Privacy → Submit}.
\item Confirmed UI fields from FR-08.2 are display name, username, avatar, short bio, university, major, and academic year; hobbies and oftenFreeTime are recommendations from the \texttt{userstory.md} profile settings flow.
\item Recommended components in \texttt{settings.md}: \texttt{ProfileSettingsForm}, \texttt{AvatarUploader}, \texttt{AvatarCropper}, \texttt{ShortBioTextarea}, \texttt{UniversitySelect}, \texttt{MajorSelect}, \texttt{AcademicYearSelect}, \texttt{HobbiesTagInput}, \texttt{OftenFreeTimeInput}, \texttt{FieldVisibilitySelect}, \texttt{ProfilePreviewPane}, \texttt{UpdateProfileButton}.
\item Exact UI text: \textbf{Update Profile}, \textbf{Save Changes}, \textbf{Discard}, \textbf{You have unsaved changes}, and \textbf{Profile updated} are labels or feedback given in \texttt{settings.md}.
\item Data fields listed in \texttt{settings.md}: \texttt{displayName}, \texttt{username}, \texttt{avatarUrl}, \texttt{shortBio}, \texttt{university}, \texttt{major}, \texttt{academicYear}, \texttt{hobbies}, \texttt{oftenFreeTime}.
\item Confirmed validation limits: PNG, JPG, WEBP, maximum 5MB, and 1:1 crop (AC-08.5); no other numeric profile limit is specified in proposals.
\item API: no dedicated profile endpoint, status code, or error code is documented in \texttt{API.md}; \texttt{/settings} and \texttt{/settings/profile} in \texttt{settings.md} are recommended route names, not confirmed requirements.
\item Privacy rule: field-level \textbf{Hidden / Visible} values are previewed here but enforced with UC-14; the success toast \textbf{Profile updated} is recommended in \texttt{settings.md}.
\end{itemize}

\par\medskip

\hypertarget{sec:b1-brief-description}{}
\addcontentsline{toc}{subsubsection}{B1. Brief Description}
\subsubsection*{B1. Brief Description}
\par\medskip

A university student specifies current courses, subjects and topics of interest, learning goals, and preferred study times so that the platform can recommend relevant forum discussions and resources. Preferences are used for forum posts, materials, study partners, and optional rooms.
\par\medskip

The student can complete preferences during onboarding after OTP verification or update them at any time from \textbf{Preferences} in \textbf{Settings}. Updating preferences refreshes the relevance of recommendations.
\par\medskip

\hypertarget{sec:b2-preconditions}{}
\addcontentsline{toc}{subsubsection}{B2. Preconditions}
\subsubsection*{B2. Preconditions}
\par\medskip

\begin{enumerate}
\item The student is authenticated before accessing protected preference settings (NFR-SEC-1).
\item During onboarding, OTP verification has succeeded and the student has been authorized to proceed to Preference Settings (FR-01.31).
\item Supported course catalog and subject or topic tag data are available (FR-09.1, FR-09.2).
\item The student has opened \textbf{Settings} and selected \textbf{Preferences}, or has followed \texttt{Register → OTP → Preference Settings}.
\end{enumerate}
\par\medskip

\hypertarget{sec:b3-postconditions}{}
\addcontentsline{toc}{subsubsection}{B3. Postconditions}
\subsubsection*{B3. Postconditions}
\par\medskip

\begin{enumerate}
\item \textbf{Success:} Current courses, subjects or topics, interests, learning goals, and preferred study times are persisted for the student.
\item \textbf{Success:} The saved preferences are available for recommendations of forum posts, materials, study partners, and optional rooms (FR-09.4, AC-09.4).
\item \textbf{Failure:} Unsupported or invalid preference inputs are not persisted and the previously saved preferences remain in effect.
\end{enumerate}
\par\medskip

\hypertarget{sec:b4-main-success-scenario-basic-flow}{}
\addcontentsline{toc}{subsubsection}{B4. Main Success Scenario (Basic Flow)}
\subsubsection*{B4. Main Success Scenario (Basic Flow)}
\par\medskip

\begin{enumerate}
\item The student opens \textbf{Preferences} in \textbf{Settings}, or reaches Preference Settings after OTP verification.
\item The system displays \texttt{PreferenceSettingsForm} with course, subject, interest, goal, and study-time controls.
\item The system shows the informational note \textbf{Preferences are used for forum posts, materials, study partners, and rooms}.
\item The student selects current courses from the supported course catalog.
\item The student selects subjects and topics of interest as checkboxes or tags and adds learning interests.
\item The student enters learning goals and selects preferred study times.
\item The student selects \textbf{Update Preferences} or \textbf{Continue}.
\item The system validates that the selections are supported, persists the preferences, and returns the student to Home during onboarding or keeps them in Settings for later edits.
\item Recommendation surfaces use the saved preferences for relevant content and partners.
\end{enumerate}
\par\medskip

At basic flow step 1, an existing student opens \textbf{Preferences} from \textbf{Settings}. After step 8, the student remains in Settings instead of being redirected to Home (FR-09.5, AC-09.5).

\paragraph*{A3. Recommendation refresh after a change}

After basic flow step 8, changed preferences refresh recommendations in the relevant forum context (FR-24.5).

A user controls the visibility of personal information so that they can protect their privacy while using the platform. Controls cover overall profile visibility, field-level visibility for academic, study-history, habit, and contact information, searchability, online status, and last-active time.
\par\medskip

The user also controls who may communicate with them through direct-message restrictions, friend-request and room-invitation controls, and muted or blocked member lists. Privacy settings must be respected wherever user information appears in posts, comments, and member lists.
\par\medskip

\hypertarget{sec:b2-preconditions}{}
\addcontentsline{toc}{subsubsection}{B2. Preconditions}
\subsubsection*{B2. Preconditions}
\par\medskip

\begin{enumerate}
\item The user is authenticated before accessing protected privacy settings (NFR-SEC-1).
\item The user has a profile whose fields can be made \textbf{Visible} or \textbf{Hidden} (FR-10.1, AC-10.1).
\item The user has opened \textbf{Settings} and selected \textbf{Privacy} or \textbf{Communication}.
\item Supported member identifiers are available for managing muted and blocked lists (FR-39.3).
\end{enumerate}
\par\medskip

\hypertarget{sec:b3-postconditions}{}
\addcontentsline{toc}{subsubsection}{B3. Postconditions}
\subsubsection*{B3. Postconditions}
\par\medskip

\begin{enumerate}
\item \textbf{Success:} Saved privacy and communication values are stored and applied consistently to posts, comments, member lists, and search results (FR-10.4, AC-10.4, NFR-PRIV-7).
\item \textbf{Success:} Disallowed messages, friend requests, or room invitations are prevented by backend enforcement (FR-39.5, NFR-SEC-6).
\item \textbf{Failure:} Unsupported values are not saved and the previously saved privacy settings remain in effect.
\end{enumerate}
\par\medskip

\hypertarget{sec:b4-main-success-scenario-basic-flow}{}
\addcontentsline{toc}{subsubsection}{B4. Main Success Scenario (Basic Flow)}
\subsubsection*{B4. Main Success Scenario (Basic Flow)}
\par\medskip

\begin{enumerate}
\item The user opens \textbf{Settings} and selects \textbf{Privacy}.
\item The system displays \texttt{PrivacySettingsForm} with \texttt{ProfileVisibilitySelect} (\textbf{Public / Private}), field-level \texttt{AcademicInfoVisibilitySelect}, \texttt{ContactInfoVisibilitySelect}, \texttt{StudyHistoryVisibilitySelect}, and \texttt{HabitsVisibilitySelect} (\textbf{Visible / Hidden}), plus \texttt{OnlineStatusToggle}, \texttt{LastActiveVisibilityToggle}, \texttt{PublicDiscoveryOptOutToggle}, and \texttt{StudyPartnerSearchOptOutToggle}.
\item The user chooses the overall profile visibility, field-level values, and search or status toggles.
\item The user opens \textbf{Communication} and sets \texttt{DirectMessageRestrictionSelect} (\textbf{Everyone / Confirmed friends only}), \texttt{FriendRequestPermissionSelect} (\textbf{Allow / Reject incoming friend requests}), and \texttt{RoomInvitationPermissionSelect} (\textbf{Allow / Reject room invitations}).
\item The user manages \texttt{MutedUsersList} and \texttt{BlockedUsersList} with \textbf{Mute}, \textbf{Unmute}, \textbf{Block}, and \textbf{Unblock}.
\item The system shows the note \textbf{Applied to posts, comments, member lists, and search results}.
\item The user selects \textbf{Save Privacy} or \textbf{Save Communication}.
\item Backend stores the values and applies them to relevant reads and interactions.
\item The system displays a success toast.
\end{enumerate}
\par\medskip

\par\medskip

\paragraph*{A2. Public discovery or study-partner search opt-out}
\par\medskip

At basic flow step 3, the user enables \texttt{PublicDiscoveryOptOutToggle} or \texttt{StudyPartnerSearchOptOutToggle} to opt out of the corresponding search results (FR-10.2, AC-10.2).
\par\medskip

\hypertarget{sec:a3-online-status-and-last-active-change}{}
\paragraph*{A3. Online status and last-active change}
\par\medskip

At basic flow step 3, the user hides or shows online status and last-active time (FR-10.3, AC-10.3, NFR-PRIV-4).
\par\medskip

\subsubsection*{B6. Exception Flows}

\hypertarget{sec:b7-business-rules}{}
\addcontentsline{toc}{subsubsection}{B7. Business Rules}
\subsubsection*{B7. Business Rules}
\par\medskip

\begin{enumerate}
\item Overall profile visibility uses \textbf{Public / Private} and provides at least two visibility levels (NFR-PRIV-1).
\item Field-level visibility uses \textbf{Visible / Hidden} for study history, habits, and contact information (FR-10.1, AC-10.1).
\item University, major, and academic year visibility is controllable (NFR-PRIV-3).
\item Online status and last-active time can be shown or hidden (FR-10.3, AC-10.3, NFR-PRIV-4).
\item Users can opt out of public discovery and study-partner search results (FR-10.2, AC-10.2).
\item Privacy settings are enforced in posts, comments, member lists, and search results (FR-10.4, AC-10.4, NFR-PRIV-7).
\item Direct messages are restricted to \textbf{Everyone / Confirmed friends only} (FR-39.4, AC-39.2, NFR-PRIV-6).
\item Friend requests offer \textbf{Allow / Reject incoming friend requests} and room invitations offer \textbf{Allow / Reject room invitations} (NFR-PRIV-2, NFR-PRIV-6).
\item Muted and blocked members are managed with \textbf{Mute}, \textbf{Unmute}, \textbf{Block}, and \textbf{Unblock} (FR-39.3, AC-39.1).
\item Communication and privacy settings must prevent interactions the user does not permit (FR-39.5, NFR-SEC-6).
\end{enumerate}

\hypertarget{sec:b10-interface-and-data-notes}{}
\addcontentsline{toc}{subsubsection}{B10. Interface and Data Notes}
\subsubsection*{B10. Interface and Data Notes}
\par\medskip

\begin{itemize}
\item Screen/flow path: \texttt{Home → Settings → Privacy}; \texttt{Home → Settings → Communication} (recommended grouping in \texttt{settings.md}); profile settings flow \texttt{Edit Description → Privacy (Hidden | Visible)}, \texttt{Edit Hobbies → Privacy}, \texttt{Privacy → Submit}.
\item Exact values from \texttt{settings.md}: \textbf{Public / Private}, \textbf{Visible / Hidden}, \textbf{Everyone / Confirmed friends only}, \textbf{Allow / Reject incoming friend requests}, \textbf{Allow / Reject room invitations}, and \textbf{Applied to posts, comments, member lists, and search results}.
\item Exact buttons and actions: \textbf{Save Privacy}, \textbf{Save Communication}, \textbf{Mute}, \textbf{Unmute}, \textbf{Block}, \textbf{Unblock}, and the \texttt{ReportBehaviorLink} label \textbf{Report inappropriate behavior}.
\item Recommended components: \texttt{PrivacySettingsForm}, \texttt{ProfileVisibilitySelect}, \texttt{AcademicInfoVisibilitySelect}, \texttt{ContactInfoVisibilitySelect}, \texttt{StudyHistoryVisibilitySelect}, \texttt{HabitsVisibilitySelect}, \texttt{OnlineStatusToggle}, \texttt{LastActiveVisibilityToggle}, \texttt{PublicDiscoveryOptOutToggle}, \texttt{StudyPartnerSearchOptOutToggle}, \texttt{DirectMessageRestrictionSelect}, \texttt{FriendRequestPermissionSelect}, \texttt{RoomInvitationPermissionSelect}, \texttt{MutedUsersList}, \texttt{BlockedUsersList}.
\item Data fields: field-level \textbf{Visible / Hidden} values for bio, habits, study history, and contact info; \texttt{onlineStatusVisible}, \texttt{lastActiveVisible}; \texttt{directMessageRestriction}, \texttt{friendRequestsEnabled}, \texttt{roomInvitationsEnabled}, \texttt{mutedUserIds}, \texttt{blockedUserIds}.
\item Routes \texttt{/settings/privacy} and \texttt{/settings/communication} are recommendations in \texttt{settings.md}; confirmed routes are Not specified in proposals.
\item API: no dedicated privacy or communication endpoint, status code, or error code is documented in \texttt{API.md}.
\item Interaction rule: room invitation controls interact with FR-38.3 and AC-38.4 notification behavior, but this use case does not redefine notification settings.
\item Enforcement rule: hidden fields must not be exposed through badges, counters, or supporting text, and backend checks are required rather than UI-only hiding (NFR-PRIV-7, NFR-SEC-6).
\end{itemize}

\hypertarget{sec:b11-source-alignment-notes}{}
\addcontentsline{toc}{subsubsection}{B11. Source Alignment Notes}
\subsubsection*{B11. Source Alignment Notes}
\par\medskip

\begin{itemize}
\item No dedicated privacy or communication API endpoints are documented in \texttt{API.md}; all route names in \texttt{settings.md} are recommendations.
\item \texttt{settings.md} treats Settings as an aggregate hub with no dedicated Settings use case; these controls are grouped from US-10 and US-39 without creating new use case IDs.
\item \texttt{friend\_profile.md} consumes these values to hide fields and restrict messaging, friend requests, and room invitations; it defines no API contract or error codes.
\item AC-39.1 and FR-39.3 mute/block management overlaps this use case only as settings control; request and message blocking flows remain in the friend and communication stories.
\end{itemize}
