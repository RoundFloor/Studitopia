\par\medskip

\hypertarget{sec:b1-brief-description}{}
\addcontentsline{toc}{subsubsection}{B1. Brief Description}
\subsubsection*{B1. Brief Description}
\par\medskip

A student enters an optional live study space by joining a public room, requesting access to a private room, or creating a new room for a study group. The trigger is the student opening the Meeting Lobby and selecting a room or \textbf{Create Room}. The successful outcome is that the student joins or creates a room and can enter the optional collaboration space. Meeting rooms are secondary supporting features and do not replace the forum as the primary collaboration space.
\par\medskip

\hypertarget{sec:b2-preconditions}{}
\addcontentsline{toc}{subsubsection}{B2. Preconditions}
\subsubsection*{B2. Preconditions}
\par\medskip

\begin{enumerate}
\item The student is authenticated with an active session.
\item The meeting-room service and real-time collaboration service are available.
\item The student is permitted to access the study-room lobby and is not blocked from room participation.
\item A room is available, or the student is permitted to create one.
\end{enumerate}
\par\medskip

\hypertarget{sec:b3-postconditions}{}
\addcontentsline{toc}{subsubsection}{B3. Postconditions}
\subsubsection*{B3. Postconditions}
\par\medskip

\begin{enumerate}
\item \textbf{Success:} The student joins a room with an available seat, or creates a room and becomes its owner or manager.
\item \textbf{Success:} The student can enter the room and use supported shared study tools according to the room configuration.
\item \textbf{Success:} Room join requests are routed to an owner or manager for a private or custom room.
\item \textbf{Failure:} The student remains outside the room and receives a clear reason, such as full capacity, rejected request, or unavailable room.
\end{enumerate}
\par\medskip

\hypertarget{sec:b4-main-success-scenario-join-a-public-room}{}
\addcontentsline{toc}{subsubsection}{B4. Main Success Scenario --- Join a Public Room}
\subsubsection*{B4. Main Success Scenario --- Join a Public Room}
\par\medskip

\begin{enumerate}
\item The student opens the Meeting Lobby.
\item The system displays available public study rooms with availability and capacity information.
\item The student selects a public room.
\item The backend verifies that the room still exists, is public, and has an available seat.
\item The backend adds the student to the room's participant list and establishes the room session.
\item The system opens the room and displays the supported shared study tools.
\item The student collaborates in the room using the available tools.
\end{enumerate}
\par\medskip

\hypertarget{sec:b5-alternative-flows}{}
\addcontentsline{toc}{subsubsection}{B5. Alternative Flows}
\subsubsection*{B5. Alternative Flows}
\par\medskip

Unless otherwise stated, an alternative flow resumes at the next step of the basic flow.
\par\medskip

\hypertarget{sec:a1-request-a-private-room}{}
\paragraph*{A1. Request a private room}
\par\medskip

At basic flow step 3, the student selects a private or custom room. The system creates a join request and notifies the room owner or manager. If accepted, the student joins the room; if rejected, the student is notified and remains in the lobby.
\par\medskip

\hypertarget{sec:a2-create-a-room}{}
\paragraph*{A2. Create a room}
\par\medskip

The student selects \textbf{Create Room}, enters a name, description, privacy level, supported tools, capacity, duration, and communication rules, and submits. The backend validates the configuration, creates the room, assigns the student as owner or manager, and opens the room.
\par\medskip

\hypertarget{sec:a3-view-room-details-before-joining}{}
\paragraph*{A3. View room details before joining}
\par\medskip

The student opens the room detail page to review capacity, description, and configuration before joining or requesting access.
\par\medskip

\hypertarget{sec:a4-room-becomes-full}{}
\paragraph*{A4. Room becomes full}
\par\medskip

At basic flow step 4, the room has no available seat. The system prevents the join, explains that the room is full, and returns the student to the lobby.
\par\medskip

\hypertarget{sec:a5-use-shared-tools}{}
\paragraph*{A5. Use shared tools}
\par\medskip

After entering the room, the student uses the shared whiteboard, shared notes, or shared timer. Updates are synchronized for all participants.
\par\medskip

\hypertarget{sec:a6-reconnect-after-interruption}{}
\paragraph*{A6. Reconnect after interruption}
\par\medskip

If the room connection is interrupted, the system attempts to restore the session and preserve shared notes without data loss.
\par\medskip

\hypertarget{sec:b6-exception-flows}{}
\addcontentsline{toc}{subsubsection}{B6. Exception Flows}
\subsubsection*{B6. Exception Flows}
\par\medskip

\hypertarget{sec:e1-private-request-rejected}{}
\paragraph*{E1. Private request rejected}
\par\medskip

The owner or manager rejects the request. The student receives a notification and cannot enter the room.
\par\medskip

\hypertarget{sec:e2-room-no-longer-exists-or-is-closed}{}
\paragraph*{E2. Room no longer exists or is closed}
\par\medskip

The system informs the student and refreshes the lobby.
\par\medskip

\hypertarget{sec:e3-capacity-race-condition}{}
\paragraph*{E3. Capacity race condition}
\par\medskip

Another student takes the last seat before the join completes. The system rejects the join and shows that the room is full.
\par\medskip

\hypertarget{sec:e4-invalid-room-configuration}{}
\paragraph*{E4. Invalid room configuration}
\par\medskip

When creating or configuring a room, the system highlights invalid values such as unsupported capacity or duration and does not create the room.
\par\medskip

\hypertarget{sec:e5-real-time-service-failure}{}
\paragraph*{E5. Real-time service failure}
\par\medskip

The student cannot enter or remain in the live room. The system reports the failure and preserves shared notes where possible.
\par\medskip

\hypertarget{sec:e6-unauthorized-or-blocked-participant}{}
\paragraph*{E6. Unauthorized or blocked participant}
\par\medskip

The backend denies room entry and explains the access restriction.
\par\medskip

\hypertarget{sec:b7-business-rules}{}
\addcontentsline{toc}{subsubsection}{B7. Business Rules}
\subsubsection*{B7. Business Rules}
\par\medskip

\begin{enumerate}
\item Meeting rooms are optional supporting features; they do not replace the forum as the primary collaboration space.
\item A public room can be joined when it has available capacity.
\item A private or custom room requires a join request that the owner or manager can accept or reject.
\item A room creator becomes the room owner or manager.
\item Room managers can configure capacity, duration, communication rules, privacy level, and supported tools.
\item Shared tool updates must be synchronized for all room participants.
\item Shared notes must be preserved during the room session and handle reconnection without data loss.
\item Room participation and invitations must respect the user's communication and privacy settings.
\end{enumerate}
\par\medskip

\hypertarget{sec:b10-interface-and-data-notes}{}
\addcontentsline{toc}{subsubsection}{B10. Interface and Data Notes}
\subsubsection*{B10. Interface and Data Notes}
\par\medskip

\begin{itemize}
\item \textbf{Screen and feature flow:} \texttt{screen\_flow.md} gives \texttt{Home -$>$ Meeting} and \texttt{Meeting -$>$ Hall Room} / \texttt{Meeting -$>$ Study Room}. \texttt{feature\_flow.md:156-173} gives \texttt{Lobby -$>$ Trending/For you/Detail -$>$ HallRoom} (via \texttt{Halls}), \texttt{Lobby -$>$ Trending/For you/Detail -$>$ StudyRoom} (via \texttt{Hub}), and \texttt{Lobby -$>$ Create -$>$ HallCreate / StudyCreate}. \texttt{Halls}, \texttt{Hub}, \texttt{HallCreate}, and \texttt{StudyCreate} are flow-derived labels with no dedicated FR or AC.
\item \textbf{Recommended routes:} \texttt{meeting\_lobby.md} suggests \texttt{/meeting} or \texttt{/meeting/lobby}; \texttt{study\_room.md} suggests \texttt{/meeting/study/:roomId} or \texttt{/meeting/hub/:roomId}, plus \texttt{/meeting/requests} for the owner/manager queue; \texttt{create\_room.md} suggests \texttt{/meeting/create} or \texttt{/meeting/rooms/new}. These routes are recommendations and are not specified in the requirements.
\item \textbf{Room-card and detail fields:} \texttt{RoomCard} shows room name, description summary, privacy badge (\textbf{Public}, \textbf{Private}, or \textbf{Custom}), availability, capacity, current occupancy, and supported tools. \texttt{RoomDetailPreviewPanel} / \texttt{StudyRoomDetailPanel} adds description, configuration, duration, and communication rules before a join or request (\texttt{FR-34.3}, \texttt{FR-35.5}, \texttt{FR-35.6}, UC-07 A3).
\item \textbf{Create-form fields:} \texttt{RoomConfigurationForm} contains exactly the seven UC-07 A2 fields --- name, description, privacy level, supported tools, capacity, duration, and communication rules. No numeric limits, minimums, maximums, or defaults for capacity or duration are specified in the sources, and none are inferred.
\item \textbf{Join-request states:} \texttt{JoinRequestDecisionBadge} / \texttt{RequestDecisionBadge} shows \texttt{Pending}, \texttt{Accepted}, or \texttt{Rejected}; \texttt{PendingRequestState} shows the requested room and time; \texttt{JoinRequestQueuePage} lets the owner or manager \textbf{Accept} or \textbf{Decline}; an accepted request joins the room and a rejected one leaves the student in the Lobby (\texttt{FR-35.3}, \texttt{FR-35.4}, AC-35.2, AC-35.3, UC-07 A1/E1).
\item \textbf{Exact UI messages in the sources (recommended copy):} Lobby --- "This room is full.", "This room is no longer available or has closed.", "You cannot access this room.", "Unable to load rooms.", "No rooms are available right now.", "Room recommendations are optional.", and "Suggestion dismissed."; room --- "Your request was rejected.", "You are not permitted to join this room.", "The live room could not be reached.", "The live room is unavailable.", "Only the owner or manager can decide requests.", "Connection interrupted. Restoring session…", "Shared notes restored.", and "Some participants are hidden by privacy settings."; create --- "Invalid capacity or duration. Room was not created.", "No numeric limits are specified for capacity or duration.", "You will be the room owner or manager.", "Room created.", "Room could not be created.", "Live collaboration service is unavailable.", and "You are not permitted to create a room.".
\item \textbf{Tool synchronization and reconnection:} \texttt{RoomToolTabs} offers \textbf{Whiteboard}, \textbf{Notes}, and \textbf{Timer}; updates must be synchronized for all participants with an update latency of 1 second or less (\texttt{FR-36.4}, AC-36.4, NFR-PERF-7). Shared notes persist during the session and must be restored without data loss after reconnection (\texttt{FR-36.6}, AC-36.6, UC-07 A6, business rule 7); \texttt{ExportWhiteboardButton} applies only when export is supported (\texttt{FR-36.5}, AC-36.5).
\item \textbf{Privacy and notification rules:} Room invitations appear only when room notifications are enabled (\texttt{FR-38.3}, AC-38.4, \texttt{RoomNotificationToggle}), and invitations may be rejected or users muted/blocked through \texttt{RoomInvitationPermissionSelect}, \texttt{MutedUsersList}, and \texttt{BlockedUsersList} (\texttt{FR-39.1}, \texttt{FR-39.3}, \texttt{FR-39.5}, NFR-PRIV-6). Participant rosters are privacy-filtered, and disallowed invitations are suppressed with "Invitations are disabled by the recipient's settings." (\texttt{NFR-PRIV-7}, \texttt{FR-39.5}).
\item \textbf{API and error contracts:} \texttt{API.md} has no room endpoints, and \texttt{response\_code.md} has no room fields or room error codes; the room API shape is unspecified. No room route, endpoint name, status code, or error code is invented for join, request, decision, or creation, and forum codes such as \texttt{48010} \texttt{FORBIDDEN} and \texttt{45000} \texttt{UNKNOWN ERROR} belong to forum/database contracts, not to rooms.
\item \textbf{Excluded legacy detail:} Fixed tables, seat assignments, invite codes, and 30-minute teardown are PA2 details and are not current requirements.
\end{itemize}

\hypertarget{sec:b1-brief-description}{}
\addcontentsline{toc}{subsubsection}{B1. Brief Description}
\subsubsection*{B1. Brief Description}
\par\medskip

A university student who is already in a Study Room or Hall Room uses the shared whiteboard, shared notes, and shared timer to collaborate on an academic problem with other participants. \texttt{AC-36.1}--\texttt{AC-36.3} and \texttt{FR-36.1}--\texttt{FR-36.3} define the three tools; \texttt{AC-36.4}/\texttt{FR-36.4} require updates to be synchronized for all participants.
\par\medskip

The use case also covers the two conditional capabilities in \texttt{AC-36.5} and \texttt{AC-36.6}: whiteboard export only when supported, and shared notes that survive reconnection without data loss. These are supporting room capabilities, not a replacement for forum-based collaboration.
\par\medskip

\hypertarget{sec:b2-preconditions}{}
\addcontentsline{toc}{subsubsection}{B2. Preconditions}
\subsubsection*{B2. Preconditions}
\par\medskip

\begin{enumerate}
\item The student is authenticated with an active session.
\item The student has entered a Study Room or Hall Room session.
\item At least one other room participant is present for collaborative use of a shared tool.
\item The room configuration supports the selected tool; whiteboard support is required for export to be relevant.
\item The real-time collaboration service is available for synchronized updates.
\end{enumerate}
\par\medskip

\hypertarget{sec:b3-postconditions}{}
\addcontentsline{toc}{subsubsection}{B3. Postconditions}
\subsubsection*{B3. Postconditions}
\par\medskip

\begin{enumerate}
\item \textbf{Success:} The selected shared tool is available to all room participants.
\item \textbf{Success:} Whiteboard, notes, and timer updates are synchronized for all participants.
\item \textbf{Success:} Shared notes are persisted during the session and restored without data loss after reconnection.
\item \textbf{Success:} Whiteboard content is exported when export is supported.
\item \textbf{Failure:} The tool remains unavailable or shows a clear synchronization/reconnection state without silently discarding shared notes.
\end{enumerate}
\par\medskip

\hypertarget{sec:b4-main-success-scenario-basic-flow}{}
\addcontentsline{toc}{subsubsection}{B4. Main Success Scenario (Basic Flow)}
\subsubsection*{B4. Main Success Scenario (Basic Flow)}
\par\medskip

\begin{enumerate}
\item The student opens the room's tool area in an active session.
\item The system presents \textbf{Whiteboard}, \textbf{Notes}, and \textbf{Timer} in \texttt{RoomToolTabs}.
\item The student selects a tool.
\item The system opens the shared tool to the student and the other room participants.
\item The student edits whiteboard content, writes shared notes, or starts/pauses/resets the shared timer.
\item The system synchronizes each update for all room participants.
\item The system shows the current synchronization state through \texttt{ToolSyncIndicator} / \texttt{NotesSyncIndicator}.
\item The student finishes the tool use and continues the room session.
\end{enumerate}
\par\medskip

\subsubsection*{B5. Alternative Flows}
\par\medskip

\hypertarget{sec:a1-export-whiteboard-content}{}
\paragraph*{A1. Export whiteboard content}
\par\medskip

At basic flow step 5, when export is supported, the student selects \textbf{Export whiteboard} (\texttt{ExportWhiteboardButton}). The system exports the current whiteboard content while leaving the shared whiteboard available to participants (\texttt{FR-36.5}, \texttt{AC-36.5}).
\par\medskip

\hypertarget{sec:a2-export-not-supported}{}
\paragraph*{A2. Export not supported}
\par\medskip

At basic flow step 5, when whiteboard export is not supported, the system does not offer the export action and shows "Export is not supported for this room." as recommended in \texttt{hall\_room.md}. No error is implied by the missing capability.
\par\medskip

\hypertarget{sec:a3-reconnect-and-restore-notes}{}
\paragraph*{A3. Reconnect and restore notes}
\par\medskip

If the connection is interrupted during the session, the system shows "Connection interrupted. Restoring session…", attempts to restore the session, and confirms with "Shared notes restored." The shared notes must not lose data (\texttt{FR-36.6}, \texttt{AC-36.6}).
\par\medskip

\hypertarget{sec:b6-exception-flows}{}
\addcontentsline{toc}{subsubsection}{B6. Exception Flows}
\subsubsection*{B6. Exception Flows}
\par\medskip

\hypertarget{sec:e1-synchronization-not-established}{}
\paragraph*{E1. Synchronization not established}
\par\medskip

The system cannot synchronize the selected tool update for all participants. It reports the failure with "The live room could not be reached." or "The live room is unavailable." and preserves notes where possible (\texttt{FR-36.4}, \texttt{FR-36.5}, \texttt{AC-36.4}).
\par\medskip

\hypertarget{sec:e2-recovery-cannot-complete}{}
\paragraph*{E2. Recovery cannot complete}
\par\medskip

The reconnection attempt does not complete. The system keeps the preserved notes where possible and shows the live-room failure notice rather than presenting an empty editor as a fresh session.
\par\medskip

\hypertarget{sec:b7-business-rules}{}
\addcontentsline{toc}{subsubsection}{B7. Business Rules}
\subsubsection*{B7. Business Rules}
\par\medskip

\begin{enumerate}
\item The room provides a shared whiteboard (\texttt{AC-36.1}, \texttt{FR-36.1}).
\item The room provides shared notes (\texttt{AC-36.2}, \texttt{FR-36.2}).
\item The room provides a shared timer (\texttt{AC-36.3}, \texttt{FR-36.3}).
\item Shared tool updates are synchronized for all room participants (\texttt{AC-36.4}, \texttt{FR-36.4}).
\item Whiteboard content can be exported only when export is supported (\texttt{AC-36.5}, \texttt{FR-36.5}).
\item Shared notes persist during the room session and handle reconnection without data loss (\texttt{AC-36.6}, \texttt{FR-36.6}).
\item Meeting rooms remain optional supporting features; the forum remains the primary collaboration space.
\end{enumerate}

\subsection*{Part B --- Use Case Specification}
\par\medskip

\hypertarget{sec:b1-brief-description}{}
\addcontentsline{toc}{subsubsection}{B1. Brief Description}
\subsubsection*{B1. Brief Description}
\par\medskip

A university student asks for academic assistance from friends, room participants, or concept learners by completing a help form with a title, subject, description, and attachments. \texttt{AC-37.1} identifies the help content, and \texttt{AC-37.2} / \texttt{FR-37.2} identify the permitted recipient groups. Other learners can accept or decline the request; the requester can cancel it or convert it into a forum post for asynchronous discussion (\texttt{AC-37.3}--\texttt{AC-37.5}). The system rate-limits requests to prevent spam (\texttt{AC-37.6}, \texttt{FR-37.6}).
\par\medskip

\hypertarget{sec:b2-preconditions}{}
\addcontentsline{toc}{subsubsection}{B2. Preconditions}
\subsubsection*{B2. Preconditions}
\par\medskip

\begin{enumerate}
\item The student is authenticated with an active session.
\item The student can reach the help area of a room session through \texttt{HelpRequestPanel} / \texttt{CreateHelpRequestButton}.
\item At least one friend, room participant, or concept learner is available as a recipient.
\item The student has not exceeded the help-request rate limit defined by the backend.
\end{enumerate}
\par\medskip

\hypertarget{sec:b3-postconditions}{}
\addcontentsline{toc}{subsubsection}{B3. Postconditions}
\subsubsection*{B3. Postconditions}
\par\medskip

\begin{enumerate}
\item \textbf{Success:} A help request is stored with \texttt{helpTitle}, \texttt{helpSubject}, \texttt{helpDescription}, \texttt{attachments}, and \texttt{recipients} as \texttt{Pending}; recipients receive it and respond with \texttt{Accepted} or \texttt{Declined}.
\item \textbf{Success:} The requester can cancel the request (\texttt{Cancelled}) or convert it into a forum post (\texttt{Converted}).
\item \textbf{Failure:} No new help request is created, and the rate-limit or validation message is shown to the requester.
\end{enumerate}
\par\medskip

\hypertarget{sec:b4-main-success-scenario-basic-flow}{}
\addcontentsline{toc}{subsubsection}{B4. Main Success Scenario (Basic Flow)}
\subsubsection*{B4. Main Success Scenario (Basic Flow)}
\par\medskip

\begin{enumerate}
\item The student selects \textbf{Request Help} in the room's help area.
\item The system opens \texttt{HelpRequestForm}.
\item The student enters \texttt{helpTitle}, \texttt{helpSubject}, and \texttt{helpDescription}, and adds \texttt{attachments}.
\item The student selects \texttt{recipients} from friends, room participants, or concept learners.
\item The student selects \textbf{Send request}.
\item The frontend validates the form fields and attachment file type/size, and the backend checks authentication, recipient eligibility, and the rate limit.
\item The system creates the help request with status \texttt{Pending} and adds it to outgoing help requests.
\item The Notification Service routes the help request to the selected recipients.
\item A recipient reviews the request in \texttt{IncomingHelpRequestList} and selects \textbf{Accept} or \textbf{Decline}.
\item The requester sees the updated status in the outgoing help request list.
\end{enumerate}
\par\medskip

\hypertarget{sec:b5-alternative-flows}{}
\addcontentsline{toc}{subsubsection}{B5. Alternative Flows}
\subsubsection*{B5. Alternative Flows}
\par\medskip

Unless otherwise stated, an alternative flow resumes at the next step of the basic flow.
\par\medskip

\hypertarget{sec:a1-recipient-accepts}{}
\paragraph*{A1. Recipient accepts}
\par\medskip

At basic flow step 10, the recipient selects \textbf{Accept}. The help request status becomes \texttt{Accepted}, and the requester is notified of the response (\texttt{FR-37.3}, \texttt{AC-37.3}).
\par\medskip

\hypertarget{sec:a2-recipient-declines}{}
\paragraph*{A2. Recipient declines}
\par\medskip

At basic flow step 10, the recipient selects \textbf{Decline}. The help request status becomes \texttt{Declined}, and the requester is notified of the response (\texttt{FR-37.3}, \texttt{AC-37.3}).
\par\medskip

\hypertarget{sec:a3-requester-cancels}{}
\paragraph*{A3. Requester cancels}
\par\medskip

The requester selects \textbf{Cancel request} on an outgoing request. The status becomes \texttt{Cancelled}, and no further responses are accepted for that request (\texttt{FR-37.4}, \texttt{AC-37.4}).
\par\medskip

\hypertarget{sec:a4-convert-to-forum-post}{}
\paragraph*{A4. Convert to forum post}
\par\medskip

The requester selects \textbf{Convert to forum post}. The system creates a forum post for asynchronous discussion and records the help request as \texttt{Converted} (\texttt{FR-37.5}, \texttt{AC-37.5}). The forum conversion uses the documented \texttt{POST /forum/posts} contract with permitted post types \texttt{discussion}, \texttt{material}, or \texttt{functional}.
\par\medskip

\hypertarget{sec:b6-exception-flows}{}
\addcontentsline{toc}{subsubsection}{B6. Exception Flows}
\subsubsection*{B6. Exception Flows}
\par\medskip

\hypertarget{sec:e1-rate-limit-reached}{}
\paragraph*{E1. Rate limit reached}
\par\medskip

The backend rejects a new request because the help-request rate limit is reached. The system shows "Too many help requests. Try again later." and does not create the request (\texttt{FR-37.6}, \texttt{AC-37.6}, \texttt{NFR-SEC-9}).
\par\medskip

\hypertarget{sec:e2-required-help-fields-missing-or-attachment-invalid}{}
\paragraph*{E2. Required help fields missing or attachment invalid}
\par\medskip

The system keeps \texttt{HelpRequestForm} open, identifies the invalid title, subject, description, attachment, or recipients, and does not submit the request (\texttt{AC-37.1}, \texttt{NFR-SEC-5}).
\par\medskip

\hypertarget{sec:e3-forum-conversion-fails}{}
\paragraph*{E3. Forum conversion fails}
\par\medskip

If forum post creation fails, the help request is not marked \texttt{Converted}. The documented errors for \texttt{POST /forum/posts} are \texttt{400 INVALID\_POST\_TYPE} (\texttt{48003}), \texttt{400 INVALID\_POST\_CONTENT} (\texttt{48004}), \texttt{401}, \texttt{403 FORBIDDEN} (\texttt{48010}), and \texttt{500 (DATABASE\_ERROR | UNKNOWN\_ERROR)}.
\par\medskip

\addcontentsline{toc}{subsubsection}{B7. Business Rules}
\subsubsection*{B7. Business Rules}
\par\medskip

\begin{enumerate}
\item A help request includes a title, subject, description, and attachments (\texttt{AC-37.1}).
\item Recipients are friends, room participants, or concept learners (\texttt{AC-37.2}, \texttt{FR-37.2}).
\item Other learners can accept or decline a help request (\texttt{AC-37.3}, \texttt{FR-37.3}).
\item The requester can cancel the help request (\texttt{AC-37.4}, \texttt{FR-37.4}).
\item A help request can be converted into a forum post (\texttt{AC-37.5}, \texttt{FR-37.5}).
\item Help requests are rate-limited to prevent spam (\texttt{AC-37.6}, \texttt{FR-37.6}, \texttt{NFR-SEC-9}).
\end{enumerate}

\hypertarget{sec:b10-interface-and-data-notes}{}
\addcontentsline{toc}{subsubsection}{B10. Interface and Data Notes}
\subsubsection*{B10. Interface and Data Notes}
\par\medskip

\begin{itemize}
\item \textbf{Screen/flow path:} \texttt{screen\_flow.md} gives \texttt{Home -$>$ Meeting} and \texttt{Meeting -$>$ Hall Room} / \texttt{Meeting -$>$ Study Room}; \texttt{feature\_flow.md} gives the Lobby paths to Hall Room and Study Room. \texttt{study\_room.md} and \texttt{hall\_room.md} place \texttt{HelpRequestPanel} inside the room shell.
\item \textbf{Form fields and actions:} \texttt{HelpRequestForm} collects \texttt{helpTitle} (\textbf{Title}), \texttt{helpSubject} (\textbf{Subject}), \texttt{helpDescription} (\textbf{Description}), and \texttt{attachments} (\textbf{Attachments}). \texttt{HelpRecipientSelector} collects \texttt{recipients} (\textbf{Recipients}) from friends, room participants, or concept learners. Actions are \textbf{Request Help}, \textbf{Send request}, \textbf{Accept}, \textbf{Decline}, \textbf{Cancel request}, and \textbf{Convert to forum post}.
\item \textbf{Statuses:} \texttt{helpStatus} uses \texttt{Pending}, \texttt{Accepted}, \texttt{Declined}, \texttt{Cancelled}, and \texttt{Converted} in outgoing and incoming help lists.
\item \textbf{Exact rate-limit message:} "Too many help requests. Try again later." is the recommended \texttt{HelpRateLimitNotice} copy in \texttt{hall\_room.md}; \texttt{study\_room.md} also shows the shorter "Too many help requests."
\item \textbf{Notification rules:} \texttt{userstory.md} section 11 places Help Request under the Notification Center; \texttt{FR-38.2} / \texttt{AC-38.3} include help requests among social notifications. \texttt{settings.md} exposes \texttt{SocialNotificationToggles}, but no help-specific API is defined.
\item \textbf{Forum conversion API:} \texttt{POST /forum/posts} accepts \texttt{university\_id}, \texttt{major\_id?}, \texttt{course\_id?}, \texttt{post\_type}, \texttt{title}, \texttt{content}, \texttt{tags?}, and \texttt{files?}; success is \texttt{201 \{post\_id, created\_at\}}. Errors and codes are listed in E3 and come from \texttt{API.md} / \texttt{response\_code.md}.
\item \textbf{Help-request endpoints/statuses/error codes:} Not specified in proposals. \texttt{API.md} has no help endpoints, and \texttt{response\_code.md} has no help error codes; only the separate forum-conversion contract is available.
\end{itemize}

\hypertarget{sec:b11-source-alignment-notes}{}
\addcontentsline{toc}{subsubsection}{B11. Source Alignment Notes}
\subsubsection*{B11. Source Alignment Notes}
\par\medskip

\begin{itemize}
\item UC-07 defines the room session and names the Notification Service for join-request routing; UC-31 uses the same room context for help requests but does not repeat UC-07's join, capacity, or owner-decision rules.
\item UC-05 contributes only the forum-notification pattern after conversion; a converted help request is a new forum post and does not become a comment or answer under UC-05.
\item \texttt{FR-37.1} names title, subject, description, and attachments generally; the exact field names \texttt{helpTitle}, \texttt{helpSubject}, \texttt{helpDescription}, \texttt{attachments}, and \texttt{recipients} come from \texttt{study\_room.md} and \texttt{hall\_room.md}.
\item The Notification Service actor is source-backed by the Notification Center help-request path; \texttt{study\_room.md} and \texttt{hall\_room.md} give slightly different rate-limit copy, and the fuller "Too many help requests. Try again later." is retained.
\end{itemize}
