\hypertarget{sec:b1-brief-description}{}
\addcontentsline{toc}{subsubsection}{B1. Brief Description}
\subsubsection*{B1. Brief Description}
\par\medskip

A student publishes an academic question or general discussion in the selected university, major, and course forum. The post supports a title, text content, optional LaTeX, optional images, and tags. The trigger is the student selecting \textbf{Create Post} and choosing the discussion-post path; the successful outcome is a validated discussion post published in the selected forum context.
\par\medskip

\hypertarget{sec:b2-preconditions}{}
\addcontentsline{toc}{subsubsection}{B2. Preconditions}
\subsubsection*{B2. Preconditions}
\par\medskip

\begin{enumerate}
\item The student is authenticated with an active session.
\item The student has selected a valid university, major, and course forum context.
\item The student is permitted to create posts in that forum.
\end{enumerate}
\par\medskip

\hypertarget{sec:b3-postconditions}{}
\addcontentsline{toc}{subsubsection}{B3. Postconditions}
\subsubsection*{B3. Postconditions}
\par\medskip

\begin{enumerate}
\item \textbf{Success:} A validated discussion post is stored with its author, content, post type, tags, and forum context.
\item \textbf{Success:} The post appears in the corresponding forum post list and can be opened in post detail.
\item \textbf{Failure:} No post is published, and the student receives a clear validation or system error with the opportunity to correct the content.
\end{enumerate}
\par\medskip

\hypertarget{sec:b4-main-success-scenario-basic-flow}{}
\addcontentsline{toc}{subsubsection}{B4. Main Success Scenario (Basic Flow)}
\subsubsection*{B4. Main Success Scenario (Basic Flow)}
\par\medskip

\begin{enumerate}
\item The student selects \textbf{Create Post} from the selected forum.
\item The system displays the post-type choices and the discussion post editor.
\item The system shows the active university, major, and course context for the new post.
\item The student enters a title, text content, optional LaTeX, optional images, and tags.
\item The student marks the post as a question or a general discussion.
\item The frontend validates the required content and supported image types or sizes before submission.
\item The student submits the post.
\item The backend verifies authentication, forum access, post permissions, content, and rate limits.
\item The backend stores the post with its author, post type, tags, and university, major, and course associations.
\item The system publishes the post and returns the new post result.
\item The system displays the post in the corresponding forum post list and allows the student to open its detail page.
\end{enumerate}
\par\medskip

\hypertarget{sec:b5-alternative-flows}{}
\addcontentsline{toc}{subsubsection}{B5. Alternative Flows}
\subsubsection*{B5. Alternative Flows}
\par\medskip

Unless otherwise stated, an alternative flow resumes at the next step of the basic flow.
\par\medskip

\hypertarget{sec:a1-general-discussion}{}
\paragraph*{A1. General discussion}
\par\medskip

At basic flow step 5, the student selects \textbf{General Discussion} instead of \textbf{Question}. The publication flow is unchanged, but the post is not treated as a question awaiting a true response.
\par\medskip

\hypertarget{sec:a2-question-post}{}
\paragraph*{A2. Question post}
\par\medskip

At basic flow step 5, the student selects \textbf{Question}. The post becomes eligible for answers and true-response marking after publication.
\par\medskip

\hypertarget{sec:a3-add-or-remove-optional-content}{}
\paragraph*{A3. Add or remove optional content}
\par\medskip

At basic flow step 4, the student adds or removes LaTeX, images, or tags. The editor updates the preview and validation state before submission.
\par\medskip

\hypertarget{sec:a4-cancel-creation}{}
\paragraph*{A4. Cancel creation}
\par\medskip

The student leaves the editor before submitting. No published post is created; any retained draft behavior is subject to the platform's buffering policy.
\par\medskip

\hypertarget{sec:b6-exception-flows}{}
\addcontentsline{toc}{subsubsection}{B6. Exception Flows}
\subsubsection*{B6. Exception Flows}
\par\medskip

\hypertarget{sec:e1-missing-or-invalid-content}{}
\paragraph*{E1. Missing or invalid content}
\par\medskip

The system highlights the invalid fields, keeps the editor open, and does not submit until corrected.
\par\medskip

\hypertarget{sec:e2-unsupported-or-oversized-image}{}
\paragraph*{E2. Unsupported or oversized image}
\par\medskip

The system rejects the image, identifies the constraint, and allows the student to choose another file.
\par\medskip

\hypertarget{sec:e3-forum-access-lost}{}
\paragraph*{E3. Forum access lost}
\par\medskip

If the forum context is no longer valid or the student lacks posting permission, the system rejects publication and explains the reason.
\par\medskip

\hypertarget{sec:e4-rate-limit-reached}{}
\paragraph*{E4. Rate limit reached}
\par\medskip

The system rejects the submission and informs the student to retry later.
\par\medskip

\hypertarget{sec:e5-server-or-database-failure}{}
\paragraph*{E5. Server or database failure}
\par\medskip

No post is published. The system displays a retry option and preserves the student's entered content where supported.
\par\medskip

\hypertarget{sec:b7-business-rules}{}
\addcontentsline{toc}{subsubsection}{B7. Business Rules}
\subsubsection*{B7. Business Rules}
\par\medskip

\begin{enumerate}
\item A discussion post must be associated with the selected university, major, and course.
\item A discussion post supports a title, text content, LaTeX, images, and tags.
\item The author must choose whether the post is a question or a general discussion.
\item Content must pass frontend and backend validation before publication.
\item A published post must appear in the corresponding forum post list.
\item Only authenticated and authorized students may create posts in a forum.
\item Post publication is subject to rate limiting to reduce spam and abuse.
\end{enumerate}

\hypertarget{sec:b10-interface-and-data-notes}{}
\addcontentsline{toc}{subsubsection}{B10. Interface and Data Notes}
\subsubsection*{B10. Interface and Data Notes}
\par\medskip

\begin{itemize}
\item \textbf{Screen/flow path:} \texttt{screen\_flow.md} gives \texttt{Forum -$>$ University -$>$ Major -$>$ Course -$>$ Post} and \texttt{Forum -$>$ Create Post -$>$ Post}. \texttt{feature\_flow.md} gives \texttt{Create Post -$>$ Discussion Post / Material Post / Functional Post}, with discussion content branches \texttt{Text / LaTeX}, \texttt{Image}, \texttt{Interactive Box}, and \texttt{Title}, and all post types converging on \textbf{Submit}.
\item \textbf{Editor fields and post-type choices:} The shared Create Post page offers \textbf{Discussion Post}, \textbf{Material Post}, and \textbf{Functional Post}; UC-04 covers the Discussion Post editor. Discussion fields are title, text content, optional LaTeX, optional images, and tags. The discussion category is \textbf{Question} or \textbf{General Discussion}. \texttt{create\_post.md} recommends the component names \texttt{CreatePostPage}, \texttt{PostTypeSelector}, \texttt{DiscussionEditorForm}, \texttt{PostCategorySelector}, \texttt{DiscussionContentEditor}, \texttt{LatexInsertButton}, \texttt{ImageUploadButton}, \texttt{PostPreviewPanel}, \texttt{CreatePostValidationSummary}, and \texttt{SubmitPostButton}.
\item \textbf{Context data:} The post is associated with \texttt{university\_id}, optional \texttt{major\_id}, and optional \texttt{course\_id}, and the editor shows the active university, major, and course context (\texttt{FR-14.4}, \texttt{AC-14.3}, UC-04 step 3).
\item \textbf{Validation, permission, and rate-limit rules:} Required content and supported image types/sizes are validated before submission (\texttt{FR-14.5}, design constraint). Backend checks authentication, forum access, posting permission, content, and rate limits (\texttt{NFR-SEC-6}, \texttt{NFR-SEC-8}, \texttt{NFR-SEC-9}, UC-04 step 8 and business rule 7). Concrete image formats and size limits are not specified in the sources.
\item \textbf{Exact UI messages available in the sources:} \texttt{create\_post.md} recommends \texttt{ForumAccessDeniedPanel} --- "You do not have permission to post in this forum."; \texttt{RateLimitError} --- "Too many posts. Please retry later."; \texttt{ServerFailureAlert} --- "Post could not be published."; \texttt{CreatePostSuccessToast} --- "Post published."; \texttt{UnsavedChangesDialog} --- "Discard unsaved changes?"; \texttt{DraftRestoreNotice} --- "A saved draft was restored."; \texttt{PostTitleInput} helper "Required"; \texttt{CreatePostButton} label "Create Post"; and \texttt{SubmitPostButton} label "Submit Post" or "Publish Post". These are recommended labels/copy, not mandated requirement text.
\item \textbf{API endpoint:} Backend route is \texttt{POST /forum/posts}. Body fields are \texttt{university\_id: string}, \texttt{major\_id?: string}, \texttt{course\_id?: string}, \texttt{post\_type: 'discussion' | 'material' | 'functional'}, \texttt{title: string}, \texttt{content: string}, \texttt{tags?: string[]}, and \texttt{files?: File[]}. Success is \texttt{201} with \texttt{data: \{ post\_id: string, created\_at: number \}}. Failures are \texttt{400} with \texttt{(INVALID\_POST\_TYPE | INVALID\_POST\_CONTENT)[]}, \texttt{401}, \texttt{403} with \texttt{(FORBIDDEN)[]}, and \texttt{500} with \texttt{(DATABASE\_ERROR | UNKNOWN\_ERROR)[]}.
\item \textbf{Database contract:} \texttt{studitopia.create\_forum\_post(pauthor\_id: uuid, puniversity\_id: uuid, pmajor\_id: uuid, pcourse\_id: uuid, ppost\_type: string, ptitle: string, pcontent: string, ptags: string[], pfiles: jsonb)} returns \texttt{\{post\_id: uuid, created\_at: timestamp\}}. Declared return errors are \texttt{UNKNOWN\_ERROR: 45000}, \texttt{INVALID\_POST\_TYPE: 48003}, \texttt{INVALID\_POST\_CONTENT: 48004}, and \texttt{FORBIDDEN: 48010}.
\item \textbf{Response-code register:} Forum codes include \texttt{48003} \texttt{INVALID\_POST\_TYPE}, \texttt{48004} \texttt{INVALID\_POST\_CONTENT}, and \texttt{48010} \texttt{FORBIDDEN}; backend codes also carry \texttt{45000} \texttt{UNKNOWN DATABASE ERROR}. No dedicated rate-limit status or error code is defined for post creation in \texttt{API.md} or \texttt{response\_code.md}.
\item \textbf{Post-publication surface:} The new post must appear in the corresponding forum post list; \texttt{list\_post.md} defines the post summary as title, author, post type, timestamp, vote score, comment count, solved status, and tags, and opens \texttt{PostDetailPage} with full content, metadata, discussion, attachments, and tools where present.
\item \textbf{Functional-post extra detail:} Outside the UC-04 discussion path but on the same Create Post page, \texttt{US-16} / \texttt{FR-16.1} to \texttt{FR-16.6} / \texttt{AC-16.1} to \texttt{AC-16.5} define an interactive academic tool: an immediate quiz with multiple-choice or single-choice questions, a prerequisite tree created manually or generated from a source file, or dynamic computation. \texttt{create\_post.md} recommends drag-and-drop and code authoring modes, \texttt{Auto apply}, \texttt{Simulate by click}, and mapping invalid tool content to generic \texttt{INVALID\_POST\_CONTENT} because \texttt{API.md} has no tree-specific error contract.
\end{itemize}

\hypertarget{sec:b11-source-alignment-notes}{}
\addcontentsline{toc}{subsubsection}{B11. Source Alignment Notes}
\subsubsection*{B11. Source Alignment Notes}
\par\medskip

\begin{itemize}
\item \texttt{use\_cases\_description.md} and the PA3 specification describe UC-04 as discussion-post creation only, while \texttt{overview.md}, \texttt{feature\_flow.md}, and \texttt{create\_post.md} place three post types on a shared Create Post page; material- and functional-post details are recorded only as interface context, not folded into the UC-04 basic flow.
\item The focused diagram shows only the general University Student actor, whereas \texttt{use\_cases\_model.md} and the focused model relationship table define actor generalization for specialized student actors; the inheritance is documented in A2/A3 rather than invented in the diagram.
\item \texttt{API.md} uses one \texttt{post\_type} enum for \texttt{discussion | material | functional}, but UC-04 and \texttt{FR-14.1} to \texttt{FR-14.6} constrain this use case to the discussion path.
\item \texttt{API.md} declares \texttt{files?: File[]} at the backend boundary and \texttt{pfiles: jsonb} at the database boundary; the sources do not define a separate image-only schema for UC-04 despite the editor-level image requirement.
\item Rate limiting is required by UC-04 business rule 7 and \texttt{NFR-SEC-9}, but \texttt{API.md} and \texttt{response\_code.md} define no \texttt{429} response or rate-limit error code; exception E4 and the recommended \texttt{RateLimitError} message are the only documented handling.
\item Concrete supported image formats, maximum image sizes, and upload limits are absent from the sources; \texttt{create\_post.md} deliberately avoids naming formats or limits.
\item UI routes, component names, and quoted messages in \texttt{create\_post.md} and \texttt{list\_post.md} are explicitly recommendations derived from the proposals; the requirement documents do not mandate those exact strings.
\item \texttt{FR-17}, \texttt{FR-19}, and \texttt{FR-20} are listed as related because a published Question post becomes eligible for detail, voting, answers, and true-response marking; those downstream actions belong to UC-03/UC-05 and US-19/US-20, not to the publication steps of UC-04.
\item \texttt{FR-04.1} states a 15-minute inactivity timeout while the PA3 UC-02 special requirements state 30 minutes; this conflict concerns session management and is not imported into UC-04 special requirements.
\end{itemize}
